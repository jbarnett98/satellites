Finding things: search, constellations, owners, and links that open on a satellite

A visitor can now type a name, a catalogue number or a designator and be flown to the object; pick out any of 43 constellations and fleets, or any of the top owners, and see the rest of the catalogue recede while a panel describes what they picked — how many, which shells, how high, when launched; filter by object type; and send someone a link that opens the site on that satellite with that group picked out. No new data: all of it is interface over the catalogue the page already holds.

What we just completed

  • Rules from the data, not from memory. Before writing a single constellation rule we counted name prefixes and owner codes in the live snapshot. That is where "HULIANWANG" (China's Guowang, 191 objects) and "GEESAT" (Geely, 63) came from, and why IRIDIUM and FENGYUN rules apply to payloads only — otherwise the Iridium 33 and Fengyun-1C debris would have joined the fleets they came from. Each rule's count is in the panel; 16,544 of 19,246 objects fall into a group, the rest are one-off payloads, rocket bodies and unknowns.
  • Search. A linear scan over every name per keystroke — under two milliseconds for 19k — ranked exact number › name starts with › designator starts with › name contains › number starts with, with multi-word queries requiring every word. Results are capped at 40, chosen by rank bucket in catalogue order so the scan never sorts eleven thousand Starlinks. An alias table maps common names onto catalogue names. / focuses the box from anywhere; ↑↓ Enter Esc work as expected; the empty box offers example queries.
  • Groups panel. Six categories — broadband megaconstellations, communications and IoT, navigation, Earth observation and weather, stations and recent launches, debris clouds — each row with operator and count; then the top owners by SATCAT code with names spelled out; then payload / rocket body / debris / unknown chips. Picking a group and an owner combine (Starlink ∩ United States is a legitimate if dull question; OneWeb ∩ United Kingdom less so). The summary block describes the picked set: objects and how many launched in the last 30 days, types, regimes, median perigee–apogee, the five most populated inclination bins in half-degree steps, first and latest launch dates, top owners.
  • Two ways to recede. Dim (default) keeps the rest of the catalogue on screen at 10% alpha and 70% size, so a group reads against its context; Hide removes it, so the group can be studied alone and the object count in the status bar becomes the group's. Hovering and clicking ignore dimmed objects.
  • Fly-to. The camera swings round to look down on a chosen object over 900 ms with an ease-in-out, keeping its distance; the target's direction is re-read every frame so a moving satellite stays centred; a drag interrupts it; if the layer hasn't produced positions yet (a link opened cold), the flight waits for the first frame instead of giving up.
  • Links. The address bar follows the selection and the picked group (history.replaceState, no reload, no history spam); on load, the parameters are applied once the catalogue is ready, with a fly-to for the satellite.
  • Verified: links for the ISS, Hubble and GPS; alias search for Tiangong (three modules of the Chinese station); selection from results; the flight landing on Tianhe over the Caucasus; Starlink picked out with its four shells summarised; GPS in Hide mode (40 shown). One find on the way: the app shell could be scrolled sideways by a programmatic focus; it is now overflow: clip.
Working principles honoured

Nothing was fetched, computed in the pipeline, or added as a dependency. Everything in this stage is a few hundred lines of interface over arrays already in memory, which is exactly what the static-first design was meant to make cheap.

The dependency direction holds: constellations and searchCatalog are pure functions over the catalogue with no Three.js or Svelte; the globe learned one new attribute; the interface does the combining.

Under the hood: how a pick reaches the pixels

Group membership is decided once, when a snapshot loads: every object gets one small integer, the index of the first rule that matches it (or −1). From then on a pick is two byte-per-object masks recomputed in about a millisecond whenever a setting changes, and the GPU does the rest.

Search, in one paragraph

The query is upper-cased, whitespace-collapsed and passed through the alias table. Every object's name is tested once; a numeric query is compared against the catalogue number first. Each hit gets a rank, and the first 40 are taken bucket by bucket in catalogue order — which is launch order, so "STARLINK" lists the oldest Starlinks first rather than a random forty — and only those forty are sorted by name for display. The total count is reported alongside so the footer can say "first 40 of 11,129".

The flight, in one paragraph

A flight stores the camera's starting direction and the target object's index. Every frame it re-reads the object's current world position (the same extrapolation the shader draws), eases a blend factor from 0 to 1 over 900 ms, interpolates between the two unit directions, and places the camera along the result at its original distance, looking at the Earth's centre. Because the direction is re-read each frame the camera lands on a moving satellite, not where it was when the flight began. A drag cancels it; a request that arrives before the first positions simply waits.

Open questions and risks

  • Rules will drift. A new constellation appears, a fleet gets renamed, a pattern over-matches. The counts in the panel are the audit; adding a rule is one line. A "changed since last snapshot" check could be added to the pipeline later.
  • "Owner" is the SATCAT country/organisation code, not the operator: Starlink is "US", OneWeb is "UK". The panel labels them by name but the semantics are SATCAT's.
  • Summaries are computed on the main thread — ~3 ms for Starlink, trivial for anything else. If the full 35k catalogue arrives and someone picks "United States", it is still under 10 ms.
  • Inclination bins are half a degree; fleets flown at 53.0° and 53.2° show as one bin. Fine for the summary, not for engineering.
  • Links reference catalogue numbers, which are stable, but a decayed object vanishes from the snapshot and the link then opens with nothing selected. A short "not in the current catalogue" notice is a small follow-up.
  • The top bar is tight at 1280 px wide (brand · search · controls). It fits; at 1920 it breathes. Narrower than 1280 is outside the desktop-only remit.

Running it

npm run dev                     # http://localhost:5173 — try /?sat=25544&group=stations or /?group=gps
npm run check                   # clean
npm run build                   # main 690 KB (184 KB gzipped), worker 21 KB

In the page: / to search; type a name, number or designator; Enter or click to select and fly. Groups for constellations, owners and types; Dim or Hide; Clear. The card's Locate re-centres; its group chip picks the group out. The address bar always holds a link to what you're looking at.
